# Dungeon Echo Localization Contract

Dungeon Echo supports `zh-CN` and `en` through one player-facing language owner: `i18n.js`.

## Goals

- A first-time English player can understand the title screen, controls, class choice, HUD, onboarding, sound settings and core combat feedback without knowing Chinese.
- Chinese remains the default for Chinese browser locales and remains fully supported.
- `?lang=en` and `?lang=zh` provide shareable direct-language links.
- Manual language choice persists locally.
- Language switching never changes gameplay state, RNG, saves, item identity or combat balance.

## Ownership

### `i18n.js`

Owns:

- language selection and persistence;
- URL language override;
- dictionary keys;
- shell/static DOM translation;
- class presentation names/descriptions;
- language switch UI;
- `de:languagechange` event.

### `i18n-runtime.js`

Owns translation of dynamic DOM still generated by legacy/core modules, for example:

- current class HUD;
- class selection cards;
- late-created touch buttons;
- late-created audio controls;
- armor-break warning presentation;
- common mana/status feedback.

It must not mutate combat state.

### Feature modules

New feature modules should call `window.DE_I18N.t(key)` for player-facing strings when practical. They must not introduce new `lang === 'en'` branches when a dictionary key is sufficient.

## Never translate identity/state fields

The following are stable program identifiers and must remain language-neutral:

- class IDs: `warrior`, `ranger`, `mage`, `assassin`;
- equipment slot IDs: `weapon`, `armor`, `helmet`, `boots`, `ring`, `amulet`;
- item icon IDs;
- monster sprite/archetype IDs;
- talent IDs;
- skill IDs;
- save keys / save schema fields;
- localStorage keys unrelated to presentation;
- URL/profile IDs;
- test markers and release markers.

Translate the displayed label, never the stored identity.

## Coverage order

1. Shell / title / HUD / controls.
2. Onboarding / sound / mobile UX.
3. Class cards and current class presentation.
4. Guardian warnings and common combat feedback.
5. Equipment names, affixes and tooltips.
6. Town / commerce / forge dynamic copy.
7. Monster names and combat log strings.
8. Guardian/finale narrative and all remaining content-system copy.
9. Achievement and historical/meta screens.

A release advertised publicly as “fully bilingual” should not ship until steps 1–8 are complete and human-smoke-tested in both languages.

## English writing style

- Prefer concise game UI English over literal translation.
- `回城` → `Return`, not a long literal explanation on buttons.
- `破甲` → `Armor Break`.
- Keep class identity consistent: `战士` Warrior, `游侠` Ranger, `秘术师` Arcanist, `刺客` Assassin.
- Keep `Dungeon Echo` as the English product name.
- Use `Floor 100`, `ATK`, `DEF`, `Crit`, `CD`, `Mana` consistently.

## Regression expectations

Localization checks must verify:

- language can switch both directions without reload;
- `?lang=en` / `?lang=zh` work;
- browser-language default works on first visit;
- manual choice persists;
- class IDs and save data do not change after switching;
- PC and mobile controls keep the same gameplay actions in both languages;
- English strings do not overflow critical HUD/touch buttons;
- no translation layer changes monster/player stats or RNG.
