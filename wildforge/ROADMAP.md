# 荒境熔炉 / Wildforge 世界模拟器长期路线

## 长期目标

Wildforge 的核心不是“再做一个 Terraria-like”，而是让玩家亲身进入一个会自行演化的 2D 沙盒世界。每个世界只保留少量真正重要的势力，资源、生态、生产、贸易、外交、战争与掠夺共同改变它们的兴衰；玩家通过探索、商旅、战斗和建设介入这套因果网络。

长期方向允许玩家在充分发展后打通其他世界，但“世界穿梭”属于后续层。当前阶段先把**单个世界本身做成可信、可观察、可干预的模拟器**。

## 不变原则

- **单世界三势力上限**：一个世界最多 3 个主要聚落/城镇/势力；附属设施不是新的独立 AI 势力。
- **宏观模拟、稀疏呈现**：人口、生产和外交在后台聚合模拟；画面只实例化玩家附近少量必要角色、商队或袭击队，禁止十几个 AI 聚落满图乱跑。
- **持久**：重要变化写入世界存档，而不是只存在于运行时。
- **单一权威**：生态、库存、市场、外交与冲突只认一份世界状态，不并存第二套经济或第二套势力状态机。
- **因果**：贸易、战争、掠夺、繁荣与衰退都必须来自可追踪的资源和决策压力。
- **玩家在世界中行动**：货物、危险与收益尽量经过真实旅途，而不是靠面板瞬移。
- **克制**：系统深度优先于单位数量；世界更“活”不等于屏幕上塞更多 AI。

## v0.8 · 世界记忆基座（已落地）

已经落地：
- `worldProgress` 持久化状态；
- 三大地貌的永久探索灯标；
- 遗物箱开启后的遗迹现场演化；
- 前哨绑定后的永久营地标记；
- 单向世界进化纪元：探索 → 三地贯通 → 三地遗迹共鸣 → 裂隙终局；
- v0.7 → v0.8 存档迁移链。

## v0.9 · 边境基础设施（已落地第一层）

目标：让玩家建设的不只是房子，而是改变移动与生存效率的“基础设施”。

计划：
- 可持久保存的路标、灯塔、补给点；
- 多个前哨之间形成路线网络；
- 长期使用的安全通道与危险区对比；
- 探索记录与世界地图提示更清晰，但不做大型独立地图系统。

本版本第一层已落地：边境路标网络（最多 8 个）、持久坐标、远方归点校准、最近路标 HUD 提示。

**v0.9.1 第二层已落地**：相邻路标派生补给路线；路线提供受限移动效率与夜间遭遇缓解；联网路标在日出积累小型地貌补给。

**v0.9.2 第三层已落地**：补给路线在世界内可见，路网连通分量会派生地貌多样性；跨地貌链路把少量另一地貌基础物资加入既有日出补给。全部继续复用同一 `infrastructure.beacons` 持久状态，不引入独立地图/路线存档。

## v0.10 · 边境市场（已落地第一层）

目标：让“跨地貌运输”第一次产生明确经济收益。

第一层：
- 每个地貌拥有不同的低价出口品与异地需求价；
- 路标成为轻量贸易站，玩家必须亲自携货跨区，不能瞬移货物；
- 铸印、每日库存与每日需求形成受限经济循环；
- 联网商路的速度、安全收益直接转化为贸易优势。

后续优先：货物容量、仓储、运输工具/驮运单位、价格波动、订单与护送风险。

## v0.11 · 据点生产与仓储

目标：贸易不再只靠玩家手挖，而是逐渐形成生产—库存—运输链。

**第一层已落地**：标准化货物与普通材料分离；每个路标附带 24 单位持久仓库；路标+工匠台可把当地原料打包成货物；玩家基础货运容量 8，货运背架扩至 16。生产、仓储、装货、运输、出售第一次形成同一条实际物流链。

计划：
- 各地貌专属生产设施与基础加工品；
- 前哨仓库和有限容量；
- 生产消耗时间/燃料/原料，而非后台凭空产出；
- 玩家决定哪些据点生产、储备、出口。

## v0.12 · 运输风险与商队

目标：让“路上发生什么”成为贸易利润的重要组成部分。

**第一层已落地**：货运载重影响移速和夜间遭遇；普通战斗受击可能把标准货物震落为可追回的世界掉落；商路、营火和货运背架分别从路线、安全区、装备三个层面降低风险。先把“亲自押货”做好，再扩展驮运单位与商队。

计划：
- 货物重量/容量；
- 夜间、危险地带、怪物袭击对货运形成真实风险；
- 简单商队/驮运工具，允许扩大单次运输规模；
- 路标、营火和前哨继续作为安全基础设施，而不是独立小游戏。

## v0.13 · 武装货运（已落地第一层）

目标：让高价值运输第一次形成“是否卸货迎战、是否雇护卫、是否走商路”的即时风险决策。第一层包含货包占手、落地货包受损、货值驱动的低频劫掠与临时护卫。

## v0.14 · 像素美术基础层（已落地第一层）

目标：先把已经成立的贸易求生闭环从“机制原型”提升为愿意继续探索的游戏画面。第一层优先覆盖玩家长期注视的地块、角色、早期敌人、护卫、货包与贸易设施；后续再扩烬风荒地、霜晶台地、运输工具与高级敌人图集。

## v0.15 · 原生操控手感层（已落地第一层）

目标：不复制 Terraria 的内容与视觉身份，但把侧视沙盒最基础的移动、跳跃、主动作、相机与输入稳定性提升到“无需适应控制器”的水平。第一层已落地固定物理步进、移动/转向调参、可变跳跃、当前物品左键语义、远程空射、近战容错、像素对齐相机与输入失焦恢复。

## v0.16 · 地表体验与基础交互层（已落地第一层）

目标：在继续堆贸易系统之前，先把玩家绝大多数时间都会接触的水平移动、物品栏、普通战斗与地表探索提升到可长期游玩的基础质量。

第一层已落地：
- 10 格快捷栏 + 40 格槽位式主物品区，物品属性与堆叠信息回归游戏槽位语法；
- 敌人受击击退与分级击退抗性；
- 普通敌人生成频率/上限整体下调，并给出生点附近的新玩家白昼缓冲；
- 世界横向从 480 扩展到 1920 格，旧存档保留旧区并生成新边境；
- 地表地貌加入分散的小型地标，不等地下内容完成才让水平探索成立。

后续继续：更多原创像素物品图标/地貌装饰、普通敌人更清晰的攻击前摇与掉落定位。

## v0.17 · 聚落需求与目的地经济（已落地第一层）

目标：让运输从单纯的异地价格差升级为明确的买家、目的地和今日订单。

第一层已落地：每个边境带拥有确定性聚落；聚落作为买方目的地，不复制路标的生产与仓储；每日优先需求提供有限数量、额外溢价与整单奖励；聚落周边拥有有限安全圈；聚落名称、需求提示和商路信号桩进入世界视图。

下一层优先：运输委托、聚落长期资源偏好、简单驮运单位，再考虑季节、灾害、资源枯竭与生态变化。生态系统只服务于供需和运输条件。


## v0.18 · Drive 美术图集整合（已落地第一层）

目标：把已经存在于 Google Drive 的原创 Wildforge 图集真正转化为运行时资产，而不是让机制成熟度继续领先于画面。

第一层已落地：统一 `core-art.webp` 继续作为唯一运行时图集；优先覆盖角色、护卫、劫匪、地表生物、路标/聚落陈设和高频物品图标，并保持程序 fallback。新增素材必须进入明确映射与来源清单，避免后续图集继续散落。

下一层优先：三地貌专属大型地标、聚落建筑轮廓、武器/工具手持图标与更完整的敌人前摇动画，然后再扩运输工具与驮运单位。

## v0.19 · 运输委托（已落地第一层）

目标：把“哪里价格高”进一步变成玩家可以主动接取、规划并完成的一趟明确商路任务，同时不另建任务货币或瞬移物流。

第一层已落地：货站按日期和起点生成确定性委托，指定本地货物、异地聚落、数量、距离、两日期限与完成奖励；接单、HUD 导航、逐件交付、逾期与完成次数全部复用 `trade` 持久状态。

下一层优先：聚落长期资源偏好与声望/可靠度的轻量反馈，然后加入第一种简单驮运单位，扩大单次运输规模但保留卸货迎战与货物受损风险。


## v0.22 · 聚落记忆与可靠度（当前）

目标：让聚落从“每日刷新的一次性买方”升级为会记住玩家长期履约表现的经济主体，同时不引入第二货币或独立声望小游戏。

第一层：
- 每个聚落拥有稳定的长期进口偏好，为固定商路提供小幅稳定溢价；
- 0–5 级可靠度按聚落独立持久化；
- 每日整单与运输委托完成提高可靠度，已接委托逾期降低可靠度；
- 更高可靠度扩大后续订单与运输委托规模并提高奖励；
- 下一轮美术优先让可靠度/长期偏好反映到聚落旗帜、货栈陈设与繁荣程度，而不是再新增一套面板系统。

## v0.23 · 商誉可视化与聚落繁荣层（基础里程碑）

目标：让 v0.22 已经成立的长期贸易关系直接改变玩家看到的世界，而不是只在数字面板里存在。

第一层已落地：聚落可靠度 0–5 级驱动居民数量、货栈陈设、旗帜、手推货车、夜间灯火和近距离商誉标识。视觉繁荣只读取现有可靠度，不建立第二套繁荣状态；完成订单/委托或违约，仍由同一套经济因果推动画面变化。

下一层优先：回到机制侧，考虑第一种真正扩大货运规模的驮运单位，同时继续保留卸货迎战、货物受损、商路和护卫的现有风险。

## v0.40 · 单世界模拟融合基底（已并入 v0.41）

目标：把旧版成熟的玩家手感、危险货运、商誉、遗迹和 Boss，与新的生态/社会/市场模拟统一到一份权威世界状态。

当前已落地：
- 世界主要势力从“每 160 格一个聚落”收敛为**固定最多三方**，分别拥有区域资源与真实库存；
- 生态、库存、人口、活力、安全和财政进入同一 `frontier` 持久状态；
- AI 商队只在非战争关系下寻找真实价差并搬运真实库存，世界同时最多 3 支商队；
- 三方关系会在通商 / 中立 / 战争之间变化；战争状态允许低频掠夺，掠夺会真实改变库存、财政、安全和活力；
- 商队与袭击队采用稀疏世界呈现，不生成大批全图漫游 NPC；
- 玩家交货、清理威胁继续反馈到同一世界状态。

下一层：把驮兽、实体物流和少量近景 NPC 接回世界，但继续遵守“宏观模拟、局部实例化”的上限。


## v0.41 · 生存与主权（已并入 v0.42）

目标：让玩家首先是一个需要活下来的普通旅人，同时让三方战争真正拥有政治终局。

当前第一层：
- 玩家拥有持久化饱食度；低饱食会降低移动效率，归零后持续失血；
- 棘鬃兽开始掉落真实食材，熔火堆可以把鲜肉加工成更高效的旅行口粮；
- 聚落战争不再允许失败方永久以极低状态苟活：势力有 `active / weakened / collapsing / annexed` 生命周期；
- 只有在战争持续、强弱差距明显、守方财政/安全/活力崩溃后，才会出现决定性进攻；决定性进攻胜利后发生吞并；
- 被吞并的聚落不会从地图删除，而是保留人口、资源和建筑，改为胜方领土并向宗主势力提供税收；
- 若一个已经拥有附属领土的势力随后被吞并，其属地一起转归新的征服者，避免出现悬空主权。

玩家长期路线不预设唯一正确答案：
- **平衡者**：通过贸易、援助和护送维持三方均势；
- **扶植者**：长期支持某一势力，帮助其赢得战争并吞并对手；
- **建国者**：中后期在满足资源、人口、据点和影响力条件后建立自己的势力；玩家势力同样计入“单世界最多三方”的硬上限。三方都仍独立时不能凭空生成第四国；玩家需要等待/促成一方失去独立性，或在已被吞并的领土上重新建国。此路线后续单独实现，不在本层仓促塞入。

之后才进入多世界层：当玩家已具备足够生产、物流与政治能力时解锁世界穿梭，让跨世界贸易成为新的增长曲线。

### Phase 0 · 发布硬化基线

当前已落地：
- `test/wildforge-current.cjs` 是 Wildforge 当前版本唯一健康度入口；仓库总 current suite 也只调用该入口，不再把历史 v0.23 测试伪装成当前权威；
- 六组固定场景种子覆盖正常发展、强势吞并、战时援助、长途运输、Boss 后世界和旧存档迁移；世界生成与 frontier 演化均锁定可重复指纹；
- 运行时提供只读 `WildforgeDiagnostics.snapshot()`，以有界样本记录帧时、frontier tick、存档耗时和实体数量；诊断状态不写入存档、不参与玩法决策；
- Phase 0 只建立可测量性与确定性，不借机增加玩法系统。

Phase 0 退出条件：`node test/wildforge-current.cjs`、`git diff --check`、固定种子指纹和真实浏览器烟测全部通过，然后才进入 Phase 1 的前 30 分钟体验重构。

## v0.42 · Phase 1 前 30 分钟体验（当前）

目标：不新增新手任务状态机，而是让现有生存、聚落、frontier 实时库存、路标与运输委托自然组成第一局体验。

当前第一层：
- 新建世界的第一座 Verdant 首府固定落在出生点约 40–72 格范围；旧 v0.41/更早存档通过持久化 `settlementLayout` 保持旧首府布局，禁止升级后“搬城”；
- 目标栏从旧的纯挖矿科技树改为：工匠台 → 基础工具 → 食物 → 首聚落 → 实时短缺 → 边境路标 → 标准货 → 真实短缺运输 → 跨区交付 → 深层成长；
- 引导里程碑复用既有 `discoveries`，不新增 onboarding 存档对象或第二套任务状态；
- 聚落把 `frontier` 的实时短缺作为第一层信息；旧“今日急需”改称“今日采购订单”，明确它是奖励层而不是世界库存权威。

Phase 1 工程退出条件：真实浏览器流程烟测、第一份运输节奏调优、移动端新手路径巡检、`node test/wildforge-current.cjs` 与仓库级 current suite 全绿。外部玩家盲测不作为当前开发硬闸门，延后到 Google Play 内测/发布验证阶段。



## v1.0 · 世界模拟贸易闭环

达到 v1.0 的标准不是“系统数量多”，而是玩家能从零开始，在一个真实运转的持久世界里完成：求生 → 探索/生产 → 观察势力供需 → 选择贸易或介入冲突 → 承担真实旅途风险 → 改变库存、关系与繁荣 → 建立长期商路，并且世界在玩家不操作时仍会自行演化。

## 当前边界

Wildforge 仍是孵化项目，不进入 `games.json`。不引入其他游戏源码，不复制 Terraria / Minecraft 的角色、敌人、配方、UI、美术或音乐身份。
